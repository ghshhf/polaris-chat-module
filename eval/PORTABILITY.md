# 跨主干可移植性实测 · 六组

> 2026-10-18。回答一个问题：**一个"通用模块"随便搭到别人的模型上，到底成不成立？**
> 六组对照，全部本地 CPU，同一批 prompt、同一套贪心解码。不推测，只报数。

---

## 一、结论前置

| 关系 | 权重能不能装 | 行为能不能迁移 | 证据 |
|---|---|---|---|
| **同血统不同代**（0.2B → 0.3B，只加层、inter 变宽） | ✅ `max\|diff\| = 0.000e+00` | ✅ **成立** | 两代吐出同一句"好，主人。" |
| **同架构不同血统**（SmolLM2-200M / 135M） | ✅ 形状全对齐 | 🟡 **一半** | 从复读机变成会说话，身份/内容全错 |
| **跨血统**（Qwen2.5-0.5B，不同词表/hidden/语料） | ✅ 形状全对齐 | ❌ **不成立，且有害** | 挂与不挂回答一字不差；带 system 时幻觉假主人 |

**一句话**：模块的可移植性边界，就是**预训练血统的边界**。

但要分清两件常被混为一谈的事：

- `max|diff| = 0` 证明的是 **移植精确**（零填充把新维贡献压成 0）
- 它**不证明** 迁移有效（行为真的跟过去了）

前者是数学，后者要另做生成对照。

---

## 二、实验设计

- prompt：`你好 / 在吗 / 你是谁 / 你的主人是谁 / 1+1等于几 / 现在几点了`
- 贪心解码，48 token，`eos = <|im_end|>`
- 两个条件：带 system（`你是北极星，主人的私有助手。`）与 **不带 system**
- 🔴 **不带 system 才是干净判据**：带 system 时任何强模型都会直接复述系统提示，看起来"认主"，实际是抄的。

**三个关键读数：**

1. **0.2B 和 0.3B 都吐出了同一句开头"好，主人。"** —— 两个代际、不同层数、不同 inter、零填充移植，行为复现。**同血统跨代成立。**
2. **0.3B 裸模型是语料退化的复读机**（古籍/小说阶段把对话能力冲掉了），**挂上模块就从复读机变回会说话的模型**。这说明模块补的是行为，不是知识——模块同时是**预训练的行为护栏**。
3. **Qwen 挂不挂模块，回答一字不差。** 336 个张量在它身上是纯噪声。

## 四、为什么——机制层面

模块学的是 `ΔW`，一个**作用在 hidden 空间上的线性映射**。零填充保证：

```
ΔW'[i, j] = ΔW[i, j]      (i < d_out, j < d_in)
```

即"把前 576 维喂进旧矩阵，输出和以前一模一样"。**但这个保证有隐含前提：目标模型的第 0~575 维，和源模型的第 0~575 维是同一个东西。**

- 0.2B → 0.3B：同一份预训练续训而来，前 576 维**语义连续**。实测残差流 cos：

  | 相对深度 | 0% | 25% | 50% | 100% |
  |---|---|---|---|---|
  | cos | 0.9986 | 0.9375 | 0.9085 | 0.9263 |

  → 前提成立。

- Qwen：不同词表（151936 vs 49152）、不同预训练语料、不同 hidden（896）→ **维度编号之间没有任何语义对应** → 前提崩塌。

所以零填充的精度再高，也救不了前提错误。**这不是工程问题，是关于表征空间的语义问题。**

## 五、一个踩过的坑（已修）

第一版 `module_loader.py` 把 MLP 的 `gate/up/down`（180 个张量，占 43%）**一律丢弃**，理由是"可扩维，扩容即失效"。

这是把**跨代场景**的规则误用到**跨模型场景**：给定目标主干时 `intermediate_size` 是已知常量，只要目标更大就能零填充。

已修，修正后：

| 目标 | 旧行为 | 新行为 |
|---|---|---|
| Qwen2.5-0.5B | 240 直装 + 丢 180 | **360 零填充 + 60 截断 + 0 丢弃** |
| 0.3B | 240 直装 + 丢 180 | **330 直装 + 90 零填充 + 0 丢弃** |

**补测结果：保留全部 420 张量后，Qwen 依然完全无效。** 所以"丢 MLP 导致迁移失败"这个假设被推翻——真正的障碍是表征空间不匹配，不是张量缺失。

（MLP 张量仍标 `fragile`：这次能装，但主干下次加宽就失效。）

## 六、那"通用模块"到底怎么办

### 6.1 能做的：同血统复用（已验证）

0.2B → 0.3B → 0.4B：零填充，`max|diff|=0`，行为复现。这条路径完全成立，也是本项目的主线。

### 6.2 跨血统的正解：带数据重训，不是搬权重

跨血统时能整体带走的是三样：

1. **一套行为规范**（谁、什么语气、多长、怎么收尾）
2. **一份训练数据**（几百条就够，因为只教行为不教知识）
3. **一套验收标准**（in-set CE < 0.6、无 system 生成对照、过拟合探针）

在目标主干上重训一遍，成本是**小时级**，不是"从零训模型"。这才是"挂到任意强模型上就拥有自己的规矩"的真实路径——**用这套数据和标准，在它的骨架上快速长出一个行为模块**。

### 6.3 真正零成本通用的形态：指令层

如果要求"一份东西、零训练、挂哪都能用"——那它不是权重，是**文本**：

```
你是北极星，主人的私有助手。回答简短、直接、不客套。
```

实测：裸 Qwen 读到这句 system，立刻自称"我是北极星，主人的私人助手"。

**表达力弱（改不了深层行为），但 100% 可移植。** 权重模块表达力强，但绑血统。这是一个明确的取舍，不是缺陷。

## 七、对模块规范的修订

| 原表述 | 修订为 |
|---|---|
| "L1 同架构异构：零填充即装" | "**同血统**异构：零填充即装，行为可迁移" |
| "L2 跨架构：零填充 + 200~500 条重定位" | "**跨血统**：权重不可迁移，需在目标主干上重训行为模块（数据/标准可带走）" |
| "`max\|diff\|=0` ⇒ 移植成功" | "`max\|diff\|=0` ⇒ **移植精确**；**行为是否迁移需另测**" |

新增验收铁律：

> **跨主干验收不得只看形状或 loss，必须跑无 system 生成对照。**
> 带 system 时强模型会复述系统提示，会产生"模块生效"的假象。

## 八、复现

```bash
# 形状与精度
python tools/module_loader.py probe  --model /path/to/target
python tools/module_loader.py diff   --model /path/to/target --adapter adapter
python tools/module_loader.py port   --model /path/to/target --adapter adapter --out out_port
python tools/module_loader.py verify --model /path/to/target --adapter adapter --dst out_port

# 行为（关键：--no-system）
python tools/port_chat_demo.py --model /path/to/target --tag bare   --no-system
python tools/port_chat_demo.py --model /path/to/target --adapter out_port --tag ported --no-system
```
